# Karina site

Личный статический сайт для GitHub Pages. Используются только HTML, CSS и Vanilla JavaScript; сервер и сборщик не нужны.

## Локальный запуск

Откройте папку проекта в VS Code и запустите `index.html` через расширение Live Server. Либо откройте файл напрямую в браузере: для обычного просмотра это работает, но `localStorage` и навигацию удобнее проверять через Live Server.

## Публикация на GitHub Pages

1. Создайте репозиторий и загрузите в него содержимое этой папки.
2. В GitHub откройте **Settings → Pages**.
3. Выберите **Deploy from a branch**, ветку `main` и папку `/ (root)`.
4. После публикации откройте адрес, который выдаст GitHub.

Все пути к страницам, скриптам и фото относительные, поэтому одинаково работают локально и на GitHub Pages.

## Структура

- `index.html`, `styles.css`, `script.js` — главная страница.
- `pages/story.html` — кинематографичная история и предложение.
- `pages/reasons.html` — 99 открытых причин и управляемая причина №100.
- `pages/garden.html` — интерактивный сад с воспоминаниями.
- `pages/page.css`, `pages/pages.js` — общие стили и логика внутренних страниц.
- `admin/` — локальная панель управления состоянием сайта.
- `assets/site-state.js` — единое хранилище состояний через `localStorage`.
- `assets/music/` — место для будущего аудиофайла.

## Фотографии

Исходная папка `pic/` в текущем проекте пуста. Десять существующих JPG лежат в корне; они не перемещались и используются по относительным путям. Чтобы заменить фотографию, поменяйте значение `src` у нужного изображения в `index.html` или `pages/story.html`.

## Причина №100 и предложение

По умолчанию `reason100Unlocked` равен `false`, поэтому карточка №100 не содержит её настоящего текста. В `admin/index.html` после подтверждения кнопки «Открыть причину №100» состояние меняется в `localStorage` и карточка становится доступной на странице причин. Там же есть действие «Скрыть причину №100». Нажатие «Да» в предложении записывает только `proposalAnswered: true` и принудительно оставляет №100 скрытой.

## Админ-панель и ограничение статического сайта

При первом посещении `admin/index.html` браузер предлагает создать локальный пароль. Он хранится только в этом браузере, а вход держится до выхода из вкладки. Это защита от случайного доступа на конкретном устройстве, но **не является безопасной авторизацией для публичного сайта**: GitHub Pages не умеет хранить секреты или проверять пароль на сервере.

Для настоящей общей авторизации и синхронизации между устройствами подключите Firebase Authentication и Firestore. Точка замены находится в `assets/site-state.js`: его методы `get()` и `set()` изолируют остальной сайт от способа хранения. После создания проекта Firebase включите Email/Password в Authentication и создайте Firestore, затем замените операции `localStorage` в этом файле на чтение и запись документа `siteState/main` с полями `reason100Unlocked`, `proposalAnswered` и `musicEnabled`. Не публикуйте секреты сервисного аккаунта в репозитории.

## Музыка

Поместите легально полученный файл, например `love-kills.mp3`, в `assets/music/`. Плеер уже имеет пользовательский интерфейс и никогда не запускается сам. После добавления файла можно подключить его к контролу в `script.js`; не включайте автозапуск.

## Изменение текста

Главный текст находится в `index.html`, история — в `pages/story.html`, а 99 причин — в массиве `reasons` файла `pages/pages.js`. Изменяйте текст в UTF-8.
